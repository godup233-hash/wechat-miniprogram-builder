# 微信小程序构建 Skill

面向中文 AI 编程助手和国内开发者的微信小程序工作流。它把“需求说清楚—先看样品—分步开发—真机测试—发布自查”固化为可执行指令，适合从零做 MVP、迭代既有小程序、修复真机问题，以及准备体验版或提审。

## 能做什么

- 一次性访谈并输出产品简报：页面、跳转、数据、隐私能力、验收标准与 v1 非目标。
- 在写原生小程序前先做浏览器交互样品，低成本确认产品和视觉方向。
- 按完整用户流程分片开发，兼顾 WXML、WXSS、JS/TS 的原生约束、状态页和输入校验。
- 根据数据是否跨设备、共享或敏感，选择本地存储、云开发或受控后端。
- 用开发者工具与 iOS/Android 真机验证，收集可复现的报错证据后再修复。
- 发布前扫描路由、AppID 配置、网络调用、URL、隐私相关 API 和 `console.log`，把“代码已改”“需在后台操作”“未验证”“受阻”明确分开。

平台后台的规则、类目、资质、备案、费用、审核周期及 API 能力都会变化；Skill 要求在提交前以微信官方文档和当前后台为准，不会把猜测写成结论。

## 使用方式

将整个目录安装或放入 AI 编程助手可发现的 Skills 目录后，用技能名调用：

```text
使用 $wechat-miniprogram-builder：我想做一个给自己用的每日喝水打卡小程序。先不要写代码；请一次性问清需求，并给我一版可确认的 v1 产品简报。
```

也可以直接给出具体任务：

```text
使用 $wechat-miniprogram-builder 检查这个小程序能否准备提审。先运行静态审计，把问题分成：代码已改、需要我去微信后台操作、未验证、受阻。不要猜后台配置。
```

Skill 中的 `references/prompt-templates.md` 提供需求访谈、原型、分片开发、报错修复、提审前审计等可直接复制的中文提示词。

## 发布前静态审计

无需第三方依赖：

```bash
python3 scripts/audit_miniprogram.py /绝对路径/你的微信小程序项目 --format markdown
```

报告只做静态盘点，不代表真机运行成功，也不代表微信后台已正确配置。仍需逐页打开、真机测试，并由账号所有者确认后台状态。
